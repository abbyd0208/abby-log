Blog 標籤篩選區 — 三案可視化比較

「我沒有很喜歡這樣的排版方式，感覺標籤佔了上面一大區塊。」

下面是現況對照組與三個方案的真實 HTML 渲染（不是圖片、不是 build 產物），色票／字級／間距都取自 globals.css 與現有元件。狀態一律是 active tag = #tools、共 3 篇。 每組右邊的「高度」是頁面載入時即時量到的值：從搜尋框下緣量到「共 N 篇」上緣，也就是篩選區實際吃掉的那一整條。

現況（對照組） – ✓無 外框卡片 + 12 顆實心 chip，就是 Abby 說「佔一大區塊」的那個
方案 1　Compact filter bar – ✗popover 降最多，但弄丟主題／類型／工具的分組語意
方案 2　Inline minimal chips推薦 – ✓無 結構全留、純樣式改動，減重感比數字更明顯

— 以下省略第 2、3 篇；展開狀態請看完整檔案 —
篩選區高度（收合）
–
優點
  • 首屏最乾淨，而且功能一個都沒少
  • 「篩選：#tools ✕」獨立一行，篩選狀態是三案裡最清楚的
  • mobile 效果最好，第一篇文章幾乎貼著搜尋框
缺點
  • 篩選入口被藏起來，個人 blog 讀者本來就少，多一次點擊會直接壓低標籤使用率
  • 點 tag = 換頁，展開狀態會被重置——選完一個 tag 面板就自己收起來
  • 展開／收合的高度跳動要配一點動畫，不然畫面會閃
  • 8 篇文章的規模其實還用不到收合
推薦程度
★★★☆☆
看完整方案 3（含展開示意 + mobile）
