### ③ 把 AI 規則放進共用 repo 前，先問：這會不會變成全隊的執行權限？

**角度**  
從「AI coding 規則進 repo」這件小事切入，講 Claude Code / AGENTS.md / hooks / settings 的協作邊界：哪些規則適合共享，哪些應留在個人本機，哪些東西其實等同於讓全隊執行一段指令。

**為什麼值得寫**  
- 很多人會把 AI 設定檔當文件看，但 hooks / MCP / settings 其實更接近 CI script 或權限設定。
- 這篇可以把「AI 協作設定」從便利性問題提升成安全與團隊治理問題。
- 有明確可複製的判準：  
  - 個人偏好不要進 repo  
  - 團隊共用規則才進 repo  
  - hook 腳本與設定必須一起 review  
  - 會自動執行的東西要用 CI 等級審查  
- 跟已發布的「全員 Claude Code」有關聯，但角度不同：那篇偏採用與工作方式，這篇偏邊界、安全與共用規則。

**素材來源**

**公開風險**  
中。素材起點來自實際團隊 repo 經驗，寫成公開文時必須抽掉所有專案背景、內部檔名、真實 hook 腳本細節、狀態檔設計、團隊決策過程。可寫成「AI coding 設定治理 checklist」，不要寫成具體案例復盤。
