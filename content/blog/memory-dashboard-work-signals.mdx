做完 AI 記憶儀表板之後，我原本以為自己會看見一個很漂亮的自動化系統。

結果比較有用的不是漂亮圖表，而是一排很不起眼的訊號：這個 session 在哪個專案、最近做了什麼、閒置了多久。

我之前已經寫過一篇 [AI 記憶儀表板](/blog/ai-memory-dashboard)，講為什麼要做它。那篇的重點是：AI 有沒有記住不是問題，問題是人看不看得到。

這篇想補的是另一件事。等我真的開始看那些資料，我才發現儀表板不只是在回答「AI 做了什麼」，它也在暴露我的工作方式。

有些問題平常感覺不到，資料攤開來就蠻尷尬。

### 1. 我以為我在多工，其實是在斷線重接

某天早上，我看著 session 列表，發現自己同時有兩三條工作線在跑。

一條是設計流程，一條是某個專案的需求整理，一條是自己的工具維護。每一條看起來都合理，每一條也都不是亂開。

但放在一起看，畫面上出現一個很明顯的模式：我不是在平行推進，我是在不同 session 之間反覆切換，然後每次切回來都要重新讀上下文。

這個成本平常很隱形。

我會覺得自己只是「順手處理一下另一件事」。但儀表板把它變成一個客觀訊號：這條線閒置了二十幾分鐘，那條線剛剛才更新，另一條線的 next step 已經停在那裡一段時間。

如果把那天早上的畫面簡化，大概長這樣：

      <th>project</th>
      <th>recent</th>

*不是真實截圖，是我把畫面匿名化後整理成的樣子。重點不是長得多漂亮，而是三條線同時攤開時，我才看見自己一直在切換。*

這時候我才意識到，AI 工作流裡的切換成本不只發生在人身上，也發生在 AI 身上。

每一次我切到新對話，都要讓它重新知道：

- 這是哪個專案
- 現在做到哪裡
- 上一輪決定了什麼
- 哪些東西不能再重做

如果這些狀態沒有被整理好，AI 看起來是在接續，其實是在重新上班。

### 2. idle time 不是偷懶，是一種工作訊號

我一開始看到 idle time，只把它當成「這個 session 多久沒動」。

後來才發現，它比我想的有用。

如果一個 session 閒置很久，但它的 next step 很明確，那代表我可能只是暫時切走。這種可以留著。

如果一個 session 閒置很久，而且 recent 裡只寫著一串模糊的描述，例如「整理中」「待確認」「繼續處理」，那就危險了。因為我回來時一定會花時間重建現場，甚至乾脆開新對話重問一次。

最麻煩的是第三種：session 看起來還活著，但其實沒有人知道它是不是已經完成。

這種在 AI 工作流裡很常見。工具沒有壞，任務也不是失敗，只是沒有被宣告結束。它就會一直躺在那裡，變成一個小小的未完成感。

儀表板讓我第一次可以看到這些未完成感堆在哪。

### 3. 我開始看「單點故障」

還有一個訊號也很有意思：某些工作只有存在於單一 session 裡。

意思是，如果那個 session 消失，或我隔天忘記它講過什麼，整件事就斷掉了。

這其實不是 AI 的問題，是我沒有把重要狀態外部化。

我後來會看一件事：這個 session 裡有沒有產出可以被下一個對話讀到的東西？

例如：

- 是否有更新專案進度檔
- 是否有寫 implementation note
- 是否有把決策放進 docs
- 是否有把下一步寫成明確清單

如果沒有，那代表所有狀態都還鎖在對話裡。這種 session 再聰明，也只是一次性的工作現場。

它沒有變成團隊記憶。

### 4. raw data 比漂亮圖表更早有用

我原本很容易想把儀表板做漂亮。加卡片、加圖表、加趨勢線，看起來比較像一個產品。

但這輪看下來，真正有用的東西其實很原始：

```text
project：這條 session 屬於哪裡
recent：最近到底做了什麼
task：目前任務是什麼
idle time：多久沒動
next：下一步能不能被一句話說清楚
```

我後來最在意的不是欄位多不多，而是它能不能讓下一輪接得上。差別通常長這樣：

```text
模糊 recent：
整理中

可接續 recent：
已整理三版首頁資訊架構，卡在「搜尋結果是否獨立成頁」，下一步等我確認方向。
```

第一種看起來有紀錄，但我回來時還是要重新問一次「你整理到哪」。第二種就算隔一天再看，也知道這條線該收尾、暫停，還是繼續往下做。

這幾個欄位不華麗，但已經足夠讓我發現兩種問題。

第一種是忙碌陷阱。畫面上有很多條線在動，看起來很有效率，但其實每條都只推一點點，沒有一條真的收尾。

第二種是交接斷點。AI 做完一輪，但沒有把結果寫到可被下一輪讀取的地方。看起來做完了，實際上只是完成在那個對話裡。

這也是為什麼我現在覺得，個人 AI 工作流的儀表板不一定要從漂亮的 chart 開始。

先把這五個欄位列出來，就很夠用了。

### 5. 儀表板不是監控 AI，是監控我和 AI 的接縫

這是我這次最大的改觀。

我一開始以為儀表板是拿來看 AI 有沒有正常工作。後來發現，它更像是在看我和 AI 之間的交接有沒有斷。

AI 產出了東西，但我有沒有看？

我做了決策，但它有沒有被寫下來？

某條工作線停了，但它是完成、暫停，還是我忘了？

這些問題都不是模型能力問題，而是工作流設計問題。

所以如果要我現在重新定義這個儀表板，我不會說它是「AI 記憶 dashboard」。

我會說它是「工作狀態的照妖鏡」。它照出來的不是 AI 多厲害，而是我到底有沒有把工作切得足夠清楚、交接得足夠乾淨。

老實說，這不一定每次都好看。但蠻有用。

### 如果你也想做類似的東西

1. **先記 raw signals，不要急著畫圖。** 專案、任務、最近做了什麼、閒置多久、下一步是什麼，這些比漂亮圖表更早有用。

2. **看交接，不只看完成。** AI 說做完不代表下一輪接得上。要看它有沒有把狀態寫到下一個對話能讀的地方。

3. **把閒置當提示，不要當罪惡感。** idle time 不是在罵你偷懶，它是在提醒：這條線是不是需要收尾、暫停，或重新定義下一步。

以上感謝收看～ 如果你也有做自己的 AI 工作儀表板，歡迎留言聊聊你最後真正會看的欄位是什麼。
