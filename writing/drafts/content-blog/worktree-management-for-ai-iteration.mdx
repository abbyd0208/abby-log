如果你開始讓多個 AI 平行改同一個專案，大概會遇到這一幕：某天早上打開電腦，家目錄底下躺著五、六個長得很像的資料夾，你分不出哪個還在用、哪個是上個月留下來的。

我前陣子就卡在這裡。當時的問題不是「開太多」——**開太多其實沒什麼成本，真正貴的是我看著這幾個資料夾，說不出它們各自停在哪。**

這篇記錄我後來怎麼整理，以及一個差點讓我做白工的坑。

### 先分清楚：branch 和 worktree 是兩層東西

這兩個詞常常被混著講，但它們解決的是不同的問題：

- **branch（分支）**＝一條獨立的修改線。它是版本控制裡的概念，不佔你桌面上的位置。
- **worktree（工作目錄）**＝一份實體存在的資料夾，裡面是這條分支當下的檔案。同一個 repo 可以同時攤開好幾份，各自停在不同分支上。

會需要 worktree，是因為 AI 要在檔案上實際動手。兩個 agent 如果共用同一個資料夾，就會互相蓋掉對方改到一半的檔案。**一個 agent 一份工作目錄，它們才不會打架。**

所以我的狀況其實是「兩層要一起管」：分支決定這條線在做什麼，工作目錄決定它現在攤在哪。而我原本只管了第一層。

### 我踩到的不是「開太多」，是「狀態不清楚」

那天實際發生的事是：我想清掉幾個看起來沒在用的資料夾，但清之前我得先回答幾個問題，而我一個都答不出來——

- 這條分支合併了沒？
- 就算合併了，下一輪的功能會不會疊在它上面？
- 這個資料夾是這個專案的，還是我另一個專案的？

答不出來，我就不敢刪。不敢刪，它們就繼續躺著，下次更難分辨。**這是個會自己滾大的問題，而它的根不在 git，在我沒把狀態寫下來。**

### 我現在的判斷順序

後來我把判斷收斂成三個問題，照順序問，一次處理一個資料夾：

**① 它屬於這個專案嗎？**

同一台機器上通常不只一個專案。我實際做的第一件事是先把「不屬於這次要清的專案」那幾個標出來，明寫「不要碰」。這條看起來廢話，但清理的時候手很快，寫下來是為了防自己。

**② 分支合併了嗎？**

沒合併的一律不動——那裡面有還沒進主線的工作。

**③ 合併了，那下一輪會不會疊在它上面？**

這是唯一需要判斷的一題，前兩題都是查證。我當時的答案是：其中一個雖然已經合併，但下一輪的功能就是要接在這塊上面繼續做，所以**保留續用**；另外兩個合併完就結束了，可以清掉。

判斷完就把結論寫進專案的狀態板，一條一行：分支叫什麼、資料夾在哪、現在什麼狀態、對應哪個任務、可不可以刪。下次要清的時候直接照著看，不用重新推理一次。

### 留下來的那個，要先做一件事

這是我差點做錯的地方。

我原本打算直接在那個保留下來的工作目錄裡繼續 commit——反正資料夾還在、AI 也熟悉那份程式碼，接著做就好。

但那條分支已經合併進主線了。**在一條已經合併的分支上繼續疊新東西，等於你的起點是「那次合併當下的樣子」，而不是現在的主線。**中間別人合進去的東西你全部沒有，等你要交出去的時候才會發現對不上。

正確的順序是三步：

```
git fetch origin
git -C <worktree 路徑> merge --ff-only origin/main
git -C <worktree 路徑> switch -c <新分支名>
```

先把這份工作目錄快轉到跟主線一樣，確認工作區是乾淨的，**然後從這裡切一條新分支**，不要沿用舊的那條。

至於確定不要的那兩個，清理是兩件事，先移除工作目錄，再刪分支：

```
git worktree remove <worktree 路徑>
git branch -d <分支名>
```

順序反過來會刪不掉——分支還被工作目錄佔著。

### 這件事跟 AI 的關係在哪

如果全部是我自己手動改，這套大概不會長出來——我一次也只開一個資料夾。

是因為讓 AI 平行做，工作目錄才會變多；也因為 AI 每次對話都從零開始，**它不會記得「這個資料夾為什麼留著」，它只會看到一堆檔案然後照著改。**所以那份狀態板不只是寫給我自己看的，它其實是寫給下一次開工的那個 agent 看的。

我後來的習慣是：開工第一件事叫 AI 讀狀態板，收工前叫它更新。工作目錄那一段就跟任務清單放在一起，不另外開檔案。

### 給同處境者的建議

1. **先練「一次一塊」，再練平行。**平行的成本不在開，在收——你得有辦法說清楚每一塊停在哪。判斷不出來的時候，同時開兩個只是同時製造兩團亂。
2. **清理之前先寫下判斷，不要邊清邊想。**三個問題照順序問：屬不屬於這個專案、合併了沒、下一輪會不會疊在上面。前兩題是查證，只有第三題需要你決定。
3. **保留下來的那個，開工前先快轉到主線再切新分支。**這是整件事裡最容易漏、代價又最實在的一步。已合併的分支不要接著 commit。

以上感謝收看～ 如果你也在管一堆平行的工作目錄，歡迎留言分享你的做法。

與AI 的工作流就是一個不斷優化與學習的過程，同一個領域的人，面對這種靈活的工具，使用的方式也不盡相同。

透過各種不同實驗，享受各種新發現、讓工作流程更順暢，讓自己不要陷入過度的資訊焦慮，共勉之！
