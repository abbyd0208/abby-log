- 目前實作：`src/components/BlogBrowser.tsx` 60–89 行

## 1. 問題分析

### 1.1 現況拆解

搜尋框下方的篩選區是一張獨立卡片，內含三列標籤 + 一行「篩選中」：

```
┌─ border-line / bg-inset / rounded-xl / px-4 py-4 ──────────────┐
│  主題   #ai-workflow 5  #design-thinking 2  #tools 3 …          │
│  類型   #tutorial 1  #reflection 3  #case-study 2 …             │
│  工具   #claude 3  #video 1                                     │
│  篩選中：#tools · 清除                                           │
└────────────────────────────────────────────────────────────────┘
```

依 CSS 推算（未實測，`py-4` + 3×26px chip 列 + 12px 列距 + 篩選中列 + 邊框 + `mt-3`）：
**整塊約佔 180px 高**。在 1440×900 的視窗、扣掉 header 與「文章」標題後，**首屏可見高度大約有四分之一被篩選區吃掉**，第一篇文章的標題被推到接近折線。

### 1.2 視覺重量從哪來（四個獨立來源）

1. **卡片外框本身**：`border + bg-inset + rounded-xl + py-4`。搜尋框已經是一個 inset 灰底方塊，篩選卡再來一個 → **同一區出現兩個互相競爭的「面」**，而且下面那個更大。上下 32px 的內距是純空氣，不承載任何資訊。
2. **chip 是實心色塊**：12 顆 chip 全部有底色（`bg-soul-bg` / `bg-memory-bg` / `bg-user-bg`），三種色系同時出現。彩度密度比下方文章卡片的 tag 還高 → **輔助控制項的視覺權重高過內容**，這是 Abby 感覺「佔一大區塊」的主因，不只是高度問題。
3. **三列是被分組標籤鎖死的**：因為每列前面要放「主題／類型／工具」，即使 tag 不多也一定佔三列，無法自然 wrap 成兩列。
4. **數字讓每顆 chip 變寬**：`#design-thinking 2` 這種長度，一列塞不了幾顆，更容易換行。

### 1.3 一個內容面的事實：一半的 tag 篩完只有 1 篇

目前 8 篇文章、12 個有文章的 tag（`figma` 為 0 已被過濾掉）：

| 分組 | tag（篇數） |
|---|---|
| 主題 | ai-workflow **5**、tools **3**、design-thinking **2**、career 1、lifestyle 1 |
| 類型 | reflection **3**、case-study **2**、mindset **2**、tutorial 1、experiment 1 |
| 工具 | claude **3**、video 1 |

**12 個 tag 裡有 5 個篩完只剩 1 篇。** 這些 tag 目前跟 `#ai-workflow`（5 篇）長得一模一樣、佔一樣的視覺份量，但對讀者的篩選價值差很多。這一點直接支撐「不需要把 12 個 tag 都以同等重量攤在首屏」。

### 1.4 目前的互動模型（會影響方案 3 的可行性）

- 搜尋 = client state（`useState`，不換頁）
- 標籤 = **URL 導航**（`/blog?tag=xxx`，Server Component 重新渲染）

也就是說，**每次點 tag 都是一次換頁**。任何「展開／收合」的本地 state，點完 tag 後預設會被重置——這是方案 3 最需要留意的地方（見 6.2）。

### 1.5 這個區塊該有的目標定位

篩選區是**輔助控制項**，成功條件是：
- 首屏第一眼看到的是「文章」；
- 想篩的人一眼找得到入口，且知道現在篩了什麼；
- 篩完之後，狀態要明顯（現在的「篩選中：#tools · 清除」藏在卡片最下面，其實很弱）。

## 2. 三種方案的 Layout

三案共同保留：搜尋功能、tag filter 功能、文章卡片結構、`tagGroups` 資料結構、URL `?tag=` 機制。

### 方案 1：Compact filter bar（一排常用 tag + 更多篩選）

```
┌──────────────────────────────────────────────────────────────┐
│ 🔍  搜尋文章標題、內文、標籤…                                  │
└──────────────────────────────────────────────────────────────┘
  #ai-workflow 5   #tools 3   #reflection 3   #claude 3   更多篩選 ▾
                                                          └─ 點開 popover：
                                                             主題 / 類型 / 工具 全清單
  共 8 篇
  ─────────────────────────────────────────────────────────────
  2026.07.28 · 9 分鐘
  如何監測自己的 AI 到底都做了什麼？…
```

- 只留一排（依 `tagCounts` 由多到少取前 4–5 個，或手動指定常用集合）。
- 其餘收進「更多篩選」下拉，下拉內容維持現在的三列分組。
- 篩選中狀態併進「共 N 篇」那一列：`共 3 篇 · 篩選中 #tools ✕`。
- 推算高度：**約 35px**（現況 ~180px，約 −80%）。

### 方案 2：Inline minimal chips（拆掉外框、chip 變輕）★ 推薦

```
┌──────────────────────────────────────────────────────────────┐
│ 🔍  搜尋文章標題、內文、標籤…                                  │
└──────────────────────────────────────────────────────────────┘
  主題  #ai-workflow 5  #design-thinking 2  #tools 3  #career 1  #lifestyle 1
  類型  #tutorial 1  #reflection 3  #case-study 2  #experiment 1  #mindset 2
  工具  #claude 3  #video 1

  共 3 篇 · 篩選中 #tools ✕
  ─────────────────────────────────────────────────────────────
```

具體做法：
- **移除卡片**：拿掉 `rounded-xl border border-line bg-inset px-4 py-4`，篩選區直接坐在頁面底色上，讓搜尋框成為這一區唯一的「面」。
- **chip 降重**：未選取狀態改成**透明底 + 淡框或純文字色**（`text-soul` / `text-memory` / `text-user` + `hover` 才上底色）；**只有 active 的 tag 保留實心底色**——顏色從「裝飾」變成「狀態指示」，這是彩度密度掉最多的一步。
- **尺寸縮一階**：`text-[12px] py-1` → `text-[11.5px] py-0.5`，列距 `space-y-3` → `gap-2`。
- 數字保留但更淡（`opacity-45`）。
- 「篩選中」從卡片底部**上移併進「共 N 篇」列**，狀態更容易被看到，同時省掉一整列。
- 推算高度：**約 90px（約 −50%）**；但因為拿掉了外框與實心色塊，**感知上的減重會比 50% 更明顯**。

### 方案 3：Collapsible filter panel（預設收合）

```
收合（預設）：
┌──────────────────────────────────────────────────────────────┐
│ 🔍  搜尋文章標題、內文、標籤…                                  │
└──────────────────────────────────────────────────────────────┘
  篩選：#tools ✕                                     展開篩選 ▾
  共 3 篇
  ─────────────────────────────────────────────────────────────

展開後：
  篩選：#tools ✕                                     收合篩選 ▴
  主題  #ai-workflow 5  #design-thinking 2  #tools 3 …
  類型  #tutorial 1  #reflection 3 …
  工具  #claude 3  #video 1
  共 3 篇
```

- 預設只有一行摘要 + 展開鈕。
- 展開後就是現在的三列（可沿用方案 2 的輕量樣式）。
- 推算高度：收合 **約 30px（−83%）**，展開時回到約 100–180px。

## 3. 優缺點

### 方案 1：Compact filter bar

| | |
|---|---|
| 優點 | 高度降最多且**不需要展開就能用**（常用 tag 直接點）；一排 chip 讀起來像麵包屑，重量最輕；照 1.3 的事實，前 4–5 個 tag 已覆蓋大多數有意義的篩選 |
| 缺點 | **失去分組語意**——讀者看不出「主題／類型／工具」三層設計；「常用」的排序規則要有人決定（自動取 count top-N 會隨發文漂移，手動指定則多一份要維護的清單）；需要 popover：click-outside、Esc 關閉、`aria-expanded`、鍵盤焦點，是三案中互動邏輯最多的 |
| 適合 | 目標是「首屏最大化給文章」，且接受標籤系統退居次要 |

### 方案 2：Inline minimal chips ★

| | |
|---|---|
| 優點 | **三層標籤結構完整保留**（這是這個 blog 的資訊架構特色，不該被藏起來）；無新增互動狀態、無 popover、無 a11y 新風險；改動幾乎純樣式，**是三案中最容易被 review、也最容易反悔的**；「未選取 = 無底色、選取 = 實心」讓顏色開始承載狀態意義，而不只是裝飾；把「篩選中」上移到 `共 N 篇` 那列，順手修掉現在狀態太弱的問題 |
| 缺點 | 高度降幅（~50%）不如另外兩案；文章數長到 20+、tag 池變滿之後，三列還是會慢慢長回來（屆時可再疊方案 1）；chip 對比度下降，需檢查淺色文字在白底的可讀性（見 7.3） |
| 適合 | 想「維持功能與結構完整、先把視覺重量壓下來」，且不想在低流量個人 blog 上增加互動成本 |

### 方案 3：Collapsible filter panel

| | |
|---|---|
| 優點 | 首屏最乾淨且功能一個不少；「篩選中」摘要獨立一行，狀態最清楚 |
| 缺點 | **篩選入口被藏起來**——個人 blog 的讀者本來就不多，多一次點擊會直接壓低標籤的使用率，等於用「幾乎沒人用的功能」換首屏；**點 tag = 換頁，展開狀態預設會被重置**（見 6.2），要額外處理否則體驗會怪；收合／展開的高度跳動需要一點動畫，不然畫面會閃 |
| 適合 | 確定「絕大多數讀者只是想看文章、幾乎不用篩選」，且願意處理狀態保存 |

## 4. 推薦

**推薦方案 2（Inline minimal chips）。**

理由（依重要性排序）：

1. **Abby 的抱怨主要是「重」，不只是「高」。** 從 1.2 看，重量的最大來源是「外框卡片 + 12 顆實心色塊」，而不是 180px 這個數字本身。方案 2 直接針對這兩個來源，是投入產出比最高的一刀。
2. **不用為了視覺犧牲資訊架構。** 三層標籤（主題／類型／工具）是這個 blog 刻意設計的分類，方案 1 會弄丟分組語意、方案 3 會把它藏起來，方案 2 兩者都保住。
3. **風險最低、可逆性最高。** 純樣式調整，沒有新 state、沒有 popover、沒有換頁狀態問題，做完不喜歡就退回，不會留下架構債。
4. **8 篇文章的規模用不到收合。** 收合／popover 是為「tag 多到攤不開」設計的，現在還沒到那個量級，先上等於提前付互動成本。

**如果做完 Abby 還是覺得太佔位**，建議的下一步是「方案 2 + 方案 1 的更多篩選」：保留輕量樣式，把「類型／工具」兩列收進「更多篩選」，主題那列留在外面。這是加法、不是重做，方案 2 不會白做。**這一步等看過方案 2 的實際畫面再決定，本輪不預先做。**

## 6. 實作風險

### 6.1 共通

| 風險 | 說明 | 對策 |
|---|---|---|
| 誤改到文章卡片的 tag | 見上方連帶影響 | `TagPill` 只新增 variant，預設值不動；改完比對 `/blog` 卡片與文章頁截圖 |
| 深色模式 | `globals.css` 若有 dark 變數，淡色／透明底 chip 的對比要重驗 | 實作前先確認專案是否有 dark theme；有的話兩個模式都要截圖 |
| Mobile 換行 | 移除分組標籤縮排或縮小 chip 後，窄螢幕的 wrap 行為會變 | 375px 寬度實測，確認不會出現孤字或破版 |
| 互動狀態 | hover / focus-visible / active 三態在新樣式下是否還分得出來 | 淡色 chip 的 hover 與 active 差異要刻意拉開；鍵盤 focus ring 不能拿掉 |

### 6.2 方案 3 專屬（也是它最大的坑）

點 tag 會導向 `/blog?tag=xxx`，Server Component 重新渲染、`BlogBrowser` 的 `useState` 重置 → **展開的面板在使用者選完 tag 後會自己收起來**。使用者若想連續換 tag，每次都要重新展開。
對策：以 `activeTag` 或 `searchParams` 推導初始展開狀態（有篩選中就預設展開）。可行，但這就是「新增狀態邏輯」，違反本輪「不要新增複雜狀態管理」的限制邊緣，需 PM 確認。

### 6.3 方案 1 專屬

- popover 需自行處理 click-outside、Esc、focus trap 與 `aria-expanded`；專案目前沒看到 headless UI 之類的依賴，**要嘛手寫、要嘛引入新套件**（後者不建議）。
- 「常用 tag」若用 count 自動排序，發文一多順序就會跳動，讀者的肌肉記憶會失效。
