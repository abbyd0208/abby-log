設計說明

核心動作
不動欄位結構（維持 820px 單欄），只把「頁面標題 / 搜尋 / 標籤」三個垂直堆疊的區塊壓成 兩列工具列：第一列＝標題＋搜尋同列，第二列＝單行標籤。標籤面板的三組 label（主題／類型／工具）拿掉，改用 chip 顏色本身表示分組。
優點
  • 首屏就看得到內容。第一篇文章從現在的 ≈444px 上移到 ≈205px，800px 首屏內從「1 篇多一點」變成「2 篇完整＋第 3 篇露頭」。
  • 風險最低。只重排 BlogBrowser 內部，不動 layout 寬度、不新增斷點、不新增元件。
  • 閱讀感最接近 Medium／個人 blog，跟文章內頁的單欄節奏一致，品牌調性不會斷。
  • 「共 3 篇 · 篩選中 #tools · 清除」變成列表上方的一條分隔線，同時扮演「狀態」和「視覺分界」，不用多一個區塊。
缺點
  • 標籤可見性下降最多。12 個標籤只露 5 個，其餘藏進「＋7 個標籤 ▾」。想靠標籤瀏覽的人要多點一次。
  • 單行工具列要決定「露哪 5 個」——依篇數排？依主題群排？這是需要拍板的取捨，沒有標準答案。
  • 捲下去之後工具列就消失（除非另外做 sticky），無法邊讀邊換標籤。
  • 資訊密度提高後，頁面上方會有點「工具列感」，比現在少一點留白的鬆弛感。
適合情境
文章數在 10～40 篇 之間、讀者主要是「從首頁／Medium 連過來，順著看最新幾篇」的個人 blog。標籤是輔助，不是主要導覽。以 Abby.log 目前 8 篇的規模，這個假設大致成立。
風險
  • 治標不治本的風險。文章長到 50 篇以上時，單行標籤列會不夠用，可能又要再改一次版型。
  • 「＋7 個標籤 ▾」的展開面板是新元件（popover / details），要處理鍵盤與外點關閉，是這案唯一的新互動成本。
  • 標題降到 19px 後，<h1> 的視覺重量和 PostCard 的 <h2>（20px）幾乎一樣——語意階層還在，但視覺上「頁面標題」會被文章標題蓋過。需要 Abby 判斷可不可接受。
