*我的個人管理儀表板*

**一個設計師做 AI 記憶系統時，撞到的不是技術問題**

「你不是說每天晚上都會自動整理嗎？我怎麼都沒看到？」

它確實有整理。每天深夜，我的電腦會自己醒過來，把我當天跟 Claude Code 所有的對話翻一遍，抽出「今天做了什麼、下一步是什麼」，寫進一個叫做 daily-log 的檔案裡。這件事它已經默默做了九天，一天都沒漏。

問題從來不是它沒記住。問題是它記住的東西，沒有一個出口。

## 我一開始解錯了題

先講背景。我是設計師，過去半年把 Claude Code 收斂成一個人工智慧助理——不是那種花俏的多代理人團隊，就是一個全能助理，餵滿我的規則跟知識。

它很快就遇到所有人都會遇到的那道牆：對話結束，記憶歸零。今天教過的事，明天要重教一次。

於是我做了跟網路上每一篇教學都一樣的事：把記憶寫成檔案。每一條規則、每一個專案狀態、每一個我的偏好，都變成一個 Markdown 檔，開新對話的時候自動載入。這一步是對的，也確實有效。

然後我開始貪心。既然記憶可以用寫的，那為什麼要我親手寫？我做了一個排程，每晚自動掃過當天的對話，自己產出日記。

我很滿意。我覺得我做完了。

但其實我只是把「我不會記錄」這個問題，換成了「有人替我記錄，但我不會去讀」。這兩件事在我腦子裡的體感完全一樣：我還是不知道昨天做到哪裡。

自動化最陰險的地方在這裡——它會製造一種完成感。排程有跑、檔案有長、日誌有寫，每一個環節都亮綠燈，只有最後一哩沒有人在意：**這些東西，人到底看不看得見？**

## 我做了一個給自己看的儀表板

我把四個散在不同角落的記憶庫——助理的行為準則、每日流水帳、我的學習筆記、工作流程手冊——全部餵進一個單頁的儀表板。一個 Python 腳本負責掃檔案，產出一份資料，一個 HTML 檔負責顯示。滑鼠點兩下就開，不用架伺服器。

**第一，我幫排程做了一條狀態列。**

![](/images/ai-memory-dashboard/02.png)

*綠點、最後執行時間、右邊那個「近 7 次失敗 1 次」——一行字就是全文的論點*

這條是整個專案裡我最喜歡的決定。排程如果某天掛掉，畫面上看起來就只是「那天沒有摘要」——可是「那天我沒工作」跟「那天它壞了」，長得一模一樣。所以我在頁首放了一行字：最後執行時間、成功還是失敗、最近七次失敗幾次。

一個看不見自己有沒有在運轉的自動化，只是在製造信任的假象。使用者要的不是「它應該有在跑」，是「我知道它有在跑」。

**第二，我把視覺一路減到底。**

第一版我用了卡片、陰影、邊框，看起來像每一個 AI 生出來的儀表板。醜倒是不醜，就是有一種塑膠感。我全部拿掉，改成分隔線加留白，圖示一律用線條的，一個表情符號都不放。

這是我自己每天要看的東西。它不需要討好我，它需要讓我一眼看到重點。

**第三，我用三層心智模型當資訊架構。**

記憶不是一坨。它至少有三種：這個助理該怎麼做事（準則）、我是誰（使用者）、現在正在進行什麼（工作記憶）。分頁就照這個分。

這聽起來很像設計師的職業病，但它解掉了一個很實際的痛：我的「進行中」專案一度累積到九條，其中四條其實早就做完了，只是沒人宣告結束。我把它們的標記從「專案」改成「參照」，面板瞬間剩五條。

資訊架構的老問題，換了個場景又出現一次。永遠是那個問題：什麼該浮上來，什麼該沉下去。

## 排程 + 儀表板 = 真正的記憶系統

排程在我睡著之後寫入，儀表板在我起床之前刷新。我打開電腦，昨天做了什麼、卡在哪裡、下一步是什麼，一頁看完。

沒有推播、沒有通知、沒有任何一個東西在跟我搶注意力。它就在那裡，等我去看。

## 瓶頸從來不在記憶

過去半年我學到最有用的事情，不是任何一個 Claude Code 的技巧。

是這個：**AI 記憶系統的瓶頸，早就不在記憶了。**

模型夠聰明了，檔案要多少有多少，排程要多密有多密。真正卡住的是最後那一段——資訊從機器的儲存空間，走到人的腦子裡的那一段。那一段沒有任何模型能幫你，那一段是設計。

所以如果你也在做這種東西，我只有一個建議：做完之後，問自己一句話。

**它跑完之後，人在哪裡看得到？**

如果答案是「檔案裡」，那你還沒做完。
