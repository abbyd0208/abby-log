### 你的團隊也缺一個會做影片的人嗎？

如果你在 SaaS 公司工作過，你一定知道這個場景：官網需要一支產品介紹影片，但團隊裡沒有動態設計師。外包一支 60 秒的 motion graphic 動輒數萬甚至十幾萬，而且來回修改的溝通成本也不低。自己學 After Effects？光是打開軟體就覺得離目標很遠。

我就是在這個處境下，用 Claude Code + Remotion，在四天內從零做出第一版 Demo，交給團隊審核。

這篇文章會完整分享我的製作流程、工具選擇、跟 AI 協作的真實體驗，以及踩過的坑。

### 為什麼選 Remotion？因為 SaaS 影片根本不需要 AE

先說我的背景：我之前工作有做過一些動畫，對 After Effects 有基本概念，但已經太久沒碰了，重新學的成本太高。

某天滑 IG 的時候，看到有人分享一個 Claude Code 的 Remotion skill。點進去研究了一下，發現 Remotion 這個框架的概念很簡單——**用 React 寫影片**。每一幀就是一個 React component 的渲染結果，動畫用 spring() 和 interpolate() 控制，寫法跟寫前端動畫幾乎一樣。

更關鍵的是，我想通了一件事：**SaaS 產品影片大多就是 motion graphic**。畫面上跑的都是 UI 介面、icon 飛入、文字 streaming、按鈕點擊這些東西——這不就是網頁嗎？網頁一定寫得出來。

加上我最近大量使用 Claude Code，等於有了一個「會寫動畫程式碼的協作者」，搭配 Remotion 的即時預覽，我覺得這條路走得通。

### 製作流程拆解

### Step 1：競品研究 → 餵 Claude Code 產企劃

第一步是研究競品怎麼做影片。我截圖了幾家競品 產品的官網影片畫面，直接丟給 Claude Code 參考。

它根據這些截圖，幫我產出了完整的企劃文件，包括：

-   產品畫面錄製腳本
-   分鏡圖設計稿

我不用從空白文件開始寫，而是在 Claude Code 產出的基礎上調整修改——這省了非常多時間。

### Step 2：分鏡規劃 → 腳本 + 視覺分鏡

腳本部分讓 Claude Code 撰寫，它根據企劃文件發展出 12 個場景的完整腳本，每場都有明確的秒數、動態描述、情緒標記。

分鏡圖的視覺呈現我則用 Gemini CLI 重新產了一次，透過 MCP 產在 Pencil 上。老實說 Claude Code 產的分鏡圖我覺得不夠好，所以這部分我選擇用更適合的工具。

**選對的工具做對的事，不用堅持一個工具打天下。**

### Step 3：場景實作 → Remotion + Google Flow

這是最核心的環節，分成兩條線：

**產品 UI 場景（Remotion）：** 因為是 SaaS 產品介紹，很多畫面需要呈現實際的產品介面。我讓 Claude Code 透過 Figma MCP 直接讀取我們的設計稿，轉成 Remotion 的 React component。一開始顏色和 icon 抓得不太準，所以我用公司的 brand skill 做了一次校準，把顏色和 icon 全部換成正確的版本。

**人物片段（Google Flow）：** 影片中穿插的真人場景——例如使用者看著螢幕、滿意地點頭——這些用 Google Flow 的 AI 生成。不需要找演員、不需要攝影棚。

### Step 4：預覽與調整 → Remotion Studio 即時預覽

Remotion 自帶一個 Studio 介面，跑 npx remotion studio 就會在 localhost:3000 開啟。左邊選場景、中間即時預覽畫面、下方有時間軸可以逐幀檢查，非常直覺。

每次修改完程式碼，畫面會即時更新。覺得不對就跟 Claude Code 說要調整——溝通方式通常是：

-   **文字描述**（最常用）：「這邊的進場效果要多一點速度感」「這個退場太慢了」
-   **截圖標註**：把預覽畫面截下來，標出哪裡不對
-   **直接指定參數**：簡單的調整就直接說要改哪個值

### Step 5：串接與交付 → CapCut 剪輯

所有場景在 Remotion 做完後，各自 render 成 mp4，再到 CapCut 裡跟 Google Flow 產的人物片段串接在一起，加上配樂，完成最終版本。

### 跟 AI 協作做動畫：什麼順、什麼卡

### 順的地方：動畫節奏的溝通

這是讓我最驚喜的部分。跟 Claude Code 描述動畫感受，它幾乎都能理解：

-   「這邊的進場效果要多一點速度感」→ 它會調整 spring 的 stiffness 和 damping
-   「這個場景需要進場跟退場」→ 它自己就能處理好 fade in/out 和位移的搭配
-   「太彈了，不要 bounce」→ 它知道要拉高 damping 值

你不需要懂動畫的參數語言，用感受描述就可以。

### 卡的地方：UI 元素的還原度

相比之下，畫面元素的細節控制是最花時間的部分。即使透過 Figma MCP 讀取了設計稿，產出的 UI 在顏色、icon、間距上還是會有落差，需要反覆校正。

這不是 Claude Code 的問題，而是「設計稿到程式碼」這件事本身就有精度損耗。只是當你習慣在 Figma 裡 pixel-perfect 地看設計，再看到程式碼產出的結果有偏差，心理落差會比較大。

**解法就是多看幾輪、持續校正。** 用 brand skill 做第一輪系統性校準，之後再逐場景微調。

### 給同樣處境的 SaaS 團隊

如果你的團隊也在猶豫要不要花大錢外包產品影片，或是不知道該不該硬學 AE，我的經驗是：

1.  **先看清需求的本質。** SaaS 產品影片的核心是 motion graphic，不是電影特效。你需要的是 UI 動態展示、文字動畫、流暢的場景轉換——這些用程式碼完全做得到。
2.  **不要執著於一個工具。** 我用了 Claude Code、Remotion、Figma MCP、Google Flow、CapCut 五六個工具。每個工具做它最擅長的事，組合起來的效果遠大於硬要一個工具解決所有問題。
3.  **AI 不會取代動態設計師，但能讓沒有設計師的團隊跨過那道門檻。** 你做出來的東西可能不是 Dribbble 上那種驚豔的作品，但絕對能達到能傳達產品價值的標準。
