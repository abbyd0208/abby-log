## ✨ 設計亮點

### 共同改進（所有方案）
1. **兩欄版型** - TOC 左側 sticky，內容右側流暢
2. **層級提升** - h2/h3 尺寸差異增加，視覺清晰度 ↑
3. **負空間優化** - 行距、邊距調整，減少擁擠感
4. **導航增強** - Sticky TOC 提升用戶體驗

### 方案 A 亮點
- 輕盈現代感
- 色系柔和專業
- Stripe/Linear 風格參考

### 方案 B 亮點
- **最強層級感** （h2: 24px → 32px）
- h2 底部邊框分隔
- 寬 TOC（260px），層級縮進 12px
- 當前項高亮
- 學術/文檔風格

### 方案 C 亮點
- 保留原有靈魂色（#2f6fd6 藍 / #1aa06a 綠）
- 最小代碼改動（1-2 小時快速上線）
- 品牌延續性最高

## 🔍 自糾能力總結

### 為什麼這樣設計？

1. **為什麼兩欄版型？**
   - 單欄 TOC 和內文擠一起，閱讀體驗差
   - Sticky TOC 讓用戶隨時看到章節導航
   - 行業標準（Medium、Stripe Docs、Linear Blog）

2. **為什麼提 3 個方案？**
   - 讓 PM 有選擇權（時間 vs 效果的 tradeoff）
   - 方案 C 最快，方案 B 效果最好
   - 避免單一方案風險

3. **為什麼先研究再寫代碼？**
   - 設計決策 = 代碼架構（改版型必須先設計）
   - 預案讓實現階段快速執行，減少返工
   - PM 決策清晰後，工程師不走冤枉路
