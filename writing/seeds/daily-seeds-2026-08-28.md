## 1. 今日可公開文章種子

### 種子 1：從「這個互動怎麼做到的？」到可落地的部落格功能

**角度**  
寫 Abby 怎麼把一個看到的網站互動／內容呈現效果，拆成「原理理解 → 可做功能 → 先做哪兩項」的 AI 協作流程。重點不是功能本身，而是：看到喜歡的設計時，怎麼用 AI 先理解機制，而不是直接叫它照抄。

**為什麼值得寫**  
- 很適合 Abby.log：是 Abby 自己的網站、自己的寫作工具改造，沒有客戶背景負擔。  
- 可以寫成「設計師如何跟 AI 拆解參考案例」的通用方法。  
- 今天素材有實際工作流：先問原理，再決定優先處理項目。  
- 可延伸成小框架：  
  1. 先問「這是怎麼做到的」  
  2. 再問「哪些部分適合我的產品」  
  3. 最後才轉成 backlog / implementation brief  

**素材來源**  
今日工作狀態紀錄裡的 Abby.log 功能優化討論。

**公開風險**  
低。注意不要貼原始截圖中可能有版權或第三方品牌細節；若引用參考網站，要標來源，並把重點放在「拆解方法」而不是複製效果。

### 種子 2：搜尋回 0 筆，不代表真的沒問題

**角度**  
寫一次 AI 工作流裡很容易發生的「靜默假陰性」：工具回 0 筆，AI 就順勢下結論說「沒有問題／已修好」，但其實搜尋方法本身可能失效。文章可以聚焦在「怎麼驗證搜尋本身有效」。

**為什麼值得寫**  
- 這是非常通用的 AI 協作坑，不依賴任何客戶產品背景。  
- 適合寫成短文或技術筆記：AI agent 做 code review、稽核、清理時都會遇到。  
- 有明確方法論：  
  - 0 筆結果以前，先做放寬版搜尋  
  - 用正向樣本確認搜尋條件有效  
  - 不把工具 exit code / 空結果直接翻譯成結論  
- 可以接到 Abby 常寫的「怎麼讓 AI 工作流少出錯」系列。

**素材來源**  
近期 AI 工作流規則驗證報告與收件匣中的候選規則。

**公開風險**  
低。可用抽象化的 grep / 搜尋案例，不要帶入原始稽核對象、內部規則檔、專案背景。

---

### 種子 3：AI 記憶系統不是倉庫，是需要定期校準的工作儀表板

**角度**  
寫 Abby 的個人 AI 記憶／工作狀態系統如何從「存很多東西」變成「每天幫我看哪些記憶需要複查、哪些規則可能過期、哪些工作狀態正在漂移」。主軸放在記憶系統的維護，而不是 dashboard 技術細節。

**為什麼值得寫**  
- 符合 Abby.log 的核心題材：個人 AI 工作流、記憶系統、儀表板反思。  
- 可以補一個很多 AI agent 使用者會遇到的問題：記憶越多不一定越好，重點是可校準、可刪、可驗證。  
- 跟今天看到的資料很貼：儀表板有生成時間、記憶層級、待 review 數、工作 session 狀態等概念。  
- 可寫成「我怎麼避免 AI 助理被過期記憶帶偏」。

**素材來源**  
個人記憶儀表板與工作狀態資料。

**公開風險**  
中。dashboard 原始資料混有工作狀態、專案資訊與路徑，公開時不能截真實畫面；建議重畫成示意圖或使用假資料。
